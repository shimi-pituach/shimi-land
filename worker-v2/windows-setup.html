🛠 התקנת ShimiWorker בווינדוז

אם החלון נסגר לך מיד בלחיצה כפולה — זה לא באג שלך ולא של הוורקר. זו מדיניות ביטחון של וינדוז שחוסמת קבצי PowerShell בדאבל-קליק וסוגרת את החלון בלי להראות את השגיאה. הפתרון: פותחים חלון בעצמנו ומריצים משם — החלון נשאר פתוח תמיד.

הסיבה הטכנית: וינדוז מגיע עם מדיניות ExecutionPolicy = Restricted. לחיצה כפולה על .ps1 מריצה אותו תחת המדיניות הזאת, הוא נחסם בשורה הראשונה, והחלון נסגר. זה קורה לכל סקריפט PowerShell בעולם, לא רק לשלנו.

הדרך שעובדת — 3 צעדים

צעד 1 — הורד וחלץ את הוורקר:
⬇ ShimiWorker-v2.0-Windows.zip
חלץ את התוכן (קליק ימני ← חלץ הכל) לתיקייה קבועה, למשל C:\ShimiWorker
צעד 2 — פתח חלור PowerShell בתיקייה של הוורקר:
החזק Shift ולחץ קליק ימני על ריק בתיקייה ← בחר "פתח חלון PowerShell כאן" (Open PowerShell window here).
אם האפשרות לא מופיע: פתח PowerShell מתפריט ההתחלה ועבור לתיקייה:
cd C:\ShimiWorker
צעד 3 — הדבק את הפקודה והמתן:
powershell -ExecutionPolicy Bypass -File install_worker_windows.ps1
ההתקנה רצה עם הצעדים כתובים מול העיניים. בגרסה החדשה של הקובץ, גם אם משהו נכשל — החלון לא נסגר אלא עוצר ומראה בדיוק מה נכשל.

אותו פתרון לסטודיו 1.4 ולהתקנת ComfyUI

קובץ ה-bat של הסטודיו וקובץ ה-ps1 של ComfyUI סובלים מאותו דבר בדיוק. מריצים אותם מתוך חלון PowerShell פתוח (צעד 2) עם:
powershell -ExecutionPolicy Bypass -File setup_lora_studio.ps1
לקובץ bat של הסטודיו 1.4, מתוך התיקייה שלו:
cmd /c "1-התקן-וינדוז.bat"

איך בודקים שהכל טוב

בתום ההתקנה, באותו חלון:
python shimi_worker.py status
python shimi_worker.py self-test
self-test שמסתיים ב"עברה בהצלחה" = הוורקר מוכן לעבודה.
