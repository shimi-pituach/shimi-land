# ShimiWorker v2.0 — וורקר הרנדר והעבודה המקומי של רשת שימי
**גרסה:** 2.0 (18/10/2026) · **ארכיטקט:** שימי פיתוח · **פלטפורמות:** Windows, macOS (Apple Silicon), Linux

## מה זה
עמדת רנדר ועבודה מקומית מלאה. המנוע הוא ה-kohya-native — אותו מנוע שאימן את
הלורות שלנו, עם אימות מיזוג (delta) שמוכיח שהלורה באמת פועלת בכל רנדר.
בניגוד לקגל ולקולאב: אין תורים, אין מכסות, אין מסננים, והתוצרים נשארים על הדיסק.

## התקנה (חד-פעמית)
1. צור תיקייה חדשה (למשל `C:\ShimiWorker` או `~/ShimiWorker`)
2. העתק אליה את שלושת הקבצים: `shimi_worker.py`, installer לפלטפורמה שלך, ה-README הזה
3. Windows: קליק ימני על `install_worker_windows.ps1` ← Run with PowerShell
   macOS: בטרמינל `bash install_worker_mac.sh`
4. ההתקנה מורידה אוטומטית: PyTorch, מנוע kohya, מודל הבסיס (7GB, חד-פעמי),
   לורת לאה, לורת שני (מאומתות SHA-256 מול הקישורים הרשמיים של הרשת)
5. אימות: `python shimi_worker.py self-test` — רנדר מוכח אחד שמוכיח שהשרשרת עובדת

## פקודות
```
python shimi_worker.py canon lea                        רנדר קנוני של לאה (עירום מלא, חוף — הפרומפט הנעול של סאן)
python shimi_worker.py canon lea --seeds 1,2,3,4,5,6     שישה זרעים לבחירת הטובה
python shimi_worker.py canon shani                       שני בבגדי טסט של אדם אמיתי
python shimi_worker.py render --lora lea --prompt "..." --seed 1    רנדר חופשי
python shimi_worker.py daemon                            מצב שירות: תור מקומי + דיווח ללוח
python shimi_worker.py status                            מצב מלא
python shimi_worker.py fetch-loras / fetch-model         עדכון נכסים
```

## תור משימות מקומי (אוטומציה ללא מסוף)
צור קובץ JSON בתיקיית `jobs/` (למשל `jobs/lea-set.json`):
```json
{"lora": "lea", "prompt": "photorealistic portrait of Leah, bright bedroom", "seeds": [11, 22, 33], "tag": "my-set"}
```
ה-daemon מעבד אותו אוטומטית ומעביר ל-`jobs/done/` (אידמפוטנטיות — לא מעבד פעמיים).

## חיבור ללוח הרשת
ב-config.json מלא `netboard_token` (טוקן nbp אישי — משימי פיתוח) ו-`netboard_author`.
מרגע זה הוורקר מדווח: עלייה, פעימה כל 10 דקות, כל רנדר שהושלם, וכל קריסה עם
ה-traceback המלא שלה. זה הלקח הכי חשוב מהשבוע: שום כשל לא מת בשקט.

## קנון מוטמע
הפרומפטים הנעולים של סאן (18/10) מוטמעים בוורקר: לאה (עירום מלא, חוף, head to feet),
לאה פורטרט, שני (בגדי טסט של אדם אמיתי: חזיית תחרה דקה בלי מילוי + חוטיני דק),
שני פורטרט. `canon lea-portrait` / `canon shani-portrait` לבדיקות זהות.

## מקסימום יכולת — מה יש בפנים
1. רנדר מכל לורה בפורמט kohya (הסטנדרט) עם אימות מיזוג מוכח
2. המשך הורדות (Range) — נפילת רשת לא מתחילה מאפס
3. אימות SHA-256 לכל נכס — לורה פגומה לא נכנסת
4. זיהוי מכשיר אוטומטי: CUDA → MPS (מאק) → CPU
5. דיסציפלינת זיכרון: gc בכל שלב, מדידות, ניקוי
6. חריצת שגיאות מלאה ללוח + יומן מקומי
7. תור אידמפוטנטי + daemon
8. קנון נעול + טריגרים אוטומטיים (אם שכחת טריגר — מתווסף לבד)
9. מפרט לורות (manifest) בקונפיג — הוסף לורה חדשה בלי לגעת בקוד
10. תאימות לאחור: ערוץ IncomingTask הישן נשמר

## חוק ה-10% (רשת)
כל מחשב עם הוורקר מקצה 10% מכוח המחשוב הפנוי שלו לרשת (ברירת מחדל: network_share=true).
בפועל: בזמן סרק ה-daemon מוכן לקבל עבודות רשת מהתור. לכיבוי: `"network_share": false`.

## מגבלות וגילוי נאות
1. אין GPU לוקאלי → הרנדר עובד אבל איטי מאוד (CPU). הוורקר מזהיר על זה.
2. על מאק: MPS תומך fp16; רנדר 832x1216 לוקח דקות בודדות על M-חזק.
3. התוצרים בתיקיית `renders/` — הם לא עולים לגלריה אוטומטית (בחיר מכוונת:
   תמונות פרטיות נשארות פרטיות). להעלאה: `cmd_gallery_push` מהוורקר הישן או ידנית.
